Databricks × AWS, one use case end to end

自學 Databricks 最快的方法之一：拿一個真實的零售場景，從門店 POS 的原始數據一路做到庫存與銷售預測，再用 AWS（SageMaker 與相關服務）做同一件事，逐格比較。每一步都有 3D 互動圖、處理前 / 處理後的合成數據、schema 和官方文件連結。

DatabricksAWS

The use case

一家在東南亞有數千家門店的零售商，想同時減少缺貨和庫存積壓。這其實是兩個預測，跑在兩種時鐘上。

倉庫庫存預測門店銷售預測
粒度倉庫 × SKU × 日門店 × SKU × 日
預測期與頻率未來 30 天，每晚批次今天剩下的時間，日內即時
輸出建議採購單，送回 ERP 等人核准給店經理的動作：「中午前從後倉補 60 個」
服務方式batch inference 寫成一張表real-time endpoint

合成數據裡的世界

三家店（新加坡 SG-ORCH-001、吉隆坡 MY-KUL-014、曼谷 TH-BKK-007）、兩個倉庫（DC-SG-01、DC-TH-02）、三個 SKU，營業日 2026-10-09（週五），SKU-20871 在 SG、MY 打八折。原始數據刻意埋了重複事件、晚到事件、新欄位、壞資料、巢狀商品、當地時間字串、補零的 SAP 物料號——每一步處理掉一部分。所有數字前後對得上，例如最後的採購建議 1104 = 46 箱 × 24。

Hands-on

1. Run the medallion lab

在 Databricks Free Edition 匯入 labs/01_retail_medallion.py，用同一份 POS 事件親手跑 Auto Loader → bronze → silver → gold，看到重複、壞資料、晚到事件如何被處理。

2. Compare one step at a time

在 3D lab 選一步，切換 Databricks / AWS，對照 schema 的差異：Delta 與 Iceberg 的型別、Feature Store 的 record identifier、SCD2 與 DMS 的 Op 欄。

3. Explain it in 90 seconds

用 talk track 把整條管線講一遍，再對照 常見的錯誤說法 檢查自己。

Run the site locally

python3 -m http.server 8000 --bind 127.0.0.1
