# Databricks vs AWS: component map

Generated from the 3D lab. Each row is one box in the diagram; the boxes sit in the same place on both stacks.

| step | Databricks | AWS | 學習重點 |
|---|---|---|---|
| 1. Sources | **Store POS terminals** (customer system)<br>Every basket becomes an event: store, SKU, quantity, price, time. Thousands of stores, with peaks on promotion days. | **Store POS terminals** (customer system)<br>Every basket becomes an event: store, SKU, quantity, price, time. Thousands of stores, with peaks on promotion days. | 兩邊起點相同：POS 是客戶系統，不屬於任何平台。先問峰值 TPS、可接受延遲、門店斷網時怎麼補送。 |
| 1. Sources | **Promo calendar, weather, holidays** (customer system)<br>Promotion plans, price changes, weather and public holidays, delivered as files or APIs. Promotions are usually the strongest demand driver. | **Promo calendar, weather, holidays** (customer system)<br>Promotion plans, price changes, weather and public holidays, delivered as files or APIs. Promotions are usually the strongest demand driver. | 促銷、價格、天氣、節日通常比換演算法更能提升準確度——設計時要優先納入。 |
| 1. Sources | **ERP and WMS (SAP, Oracle)** (customer system)<br>System of record for stock on hand per warehouse and store, open purchase orders, inbound shipments and the product master. | **ERP and WMS (SAP, Oracle)** (customer system)<br>System of record for stock on hand per warehouse and store, open purchase orders, inbound shipments and the product master. | ERP 是 system of record：兩個方案都用 CDC 讀進來，再把建議訂單寫回去，不取代 ERP。 |
| 2. Ingest | **Apache Kafka** (open source / third party)<br>Durable event buffer between tills and the platform, with replay after a bug fix. Databricks reads it with the Structured Streaming Kafka source inside a Lakeflow pipeline. The Kafka cluster itself can be Confluent or Amazon MSK.<br>[doc](https://docs.databricks.com/aws/en/connect/streaming/kafka/) | **Amazon MSK** (AWS)<br>Managed Apache Kafka. Kinesis Data Streams is the AWS-native alternative when you do not need Kafka APIs.<br>[doc](https://docs.aws.amazon.com/msk/latest/developerguide/what-is-msk.html) | Kafka 在兩邊都是平台外元件。Databricks on AWS 直接讀 MSK 很常見——這是共存點，不是競爭點。 |
| 2. Ingest | **Auto Loader** (Databricks)<br>Processes new files as they land in S3 or Unity Catalog volumes (the cloudFiles source), with schema inference and evolution and exactly-once writes to Delta. Databricks recommends it inside Lakeflow pipelines.<br>[doc](https://docs.databricks.com/aws/en/ingestion/cloud-object-storage/auto-loader/) | **S3 landing + AWS Glue jobs** (AWS)<br>Files land in an S3 prefix. Glue jobs pick up only new files using job bookmarks, on a schedule or triggered by S3 events through EventBridge.<br>[doc](https://docs.aws.amazon.com/glue/latest/dg/what-is-glue.html) | Auto Loader 只吃「檔案」，不讀 Kafka。AWS 沒有一對一的服務，通常是 S3 事件 + Glue bookmarks 組出來。 |
| 2. Ingest | **Lakeflow Connect** (Databricks)<br>Managed ingestion from databases and SaaS apps into streaming tables, with change data capture. Part of Lakeflow, next to pipelines and jobs.<br>[doc](https://docs.databricks.com/aws/en/ingestion/overview) | **Zero-ETL or AWS DMS** (AWS)<br>Zero-ETL integrations bring operational databases and apps such as SAP and Salesforce into the lakehouse in near real time. AWS DMS covers other change-data-capture sources.<br>[doc](https://docs.aws.amazon.com/glue/latest/dg/zero-etl-using.html) | Zero-ETL 對應的是 Lakeflow Connect（CDC），不是 Auto Loader。支援哪個 ERP connector 要依客戶版本確認，不要當場保證。 |
| 3. Raw (bronze) | **Structured Streaming, real-time mode** (Databricks)<br>Computes rolling features, such as units sold in the last 15 minutes per store and SKU, and writes them directly to the Online Feature Store through Stream Feature Views.<br>[doc](https://docs.databricks.com/aws/en/structured-streaming/real-time/concepts) | **Managed Service for Apache Flink** (AWS)<br>Flink applications compute windowed aggregates on MSK or Kinesis and write them to the SageMaker Feature Store online store.<br>[doc](https://docs.aws.amazon.com/managed-flink/latest/java/what-is.html) | Databricks 用同一個 Spark 引擎做批和流；AWS 常見是 Spark（Glue/EMR）做批、Flink 做流——兩套技能、兩套運維。 |
| 3. Raw (bronze) | **Bronze streaming tables** (Databricks)<br>Raw Delta tables written by the Lakeflow pipeline. Nothing is cleaned here, so silver and gold can always be rebuilt.<br>[doc](https://docs.databricks.com/aws/en/ldp/) | **Raw Iceberg tables in S3 Tables** (AWS)<br>Raw events land in Apache Iceberg tables in an S3 table bucket, written by Amazon Data Firehose or Glue streaming jobs.<br>[doc](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-tables.html) | 兩邊都是開放表格式（Delta / Iceberg），AWS 也不是封閉的。 |
| 4. Clean (silver) | **Silver: Lakeflow Spark Declarative Pipelines** (Databricks)<br>Declarative SQL or Python: dedupe, handle late events and store time zones, keep product master history. Expectations drop or quarantine bad rows and count them.<br>[doc](https://docs.databricks.com/aws/en/ldp/) | **AWS Glue ETL or EMR Serverless** (AWS)<br>Spark jobs authored in SageMaker Unified Studio notebooks or Visual ETL, running on Glue or EMR Serverless. Data quality rules check each run.<br>[doc](https://docs.aws.amazon.com/glue/latest/dg/what-is-glue.html) | DLT 已改名 Lakeflow pipelines（Spark Declarative Pipelines）。這層是 Databricks 最核心的資料工程能力，值得花最多時間練習。 |
| 5. Curated (gold) | **Gold materialized views** (Databricks)<br>Business-level tables: daily sales per store and SKU, stock position per warehouse and SKU. One source for dashboards and models, so the numbers agree.<br>[doc](https://docs.databricks.com/aws/en/ldp/) | **Curated Iceberg tables** (AWS)<br>Curated tables in the SageMaker lakehouse architecture, registered in the Glue Data Catalog and queried by Athena or Redshift.<br>[doc](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/lakehouse.html) | 一張 gold 同時餵 BI 和 ML，避免兩邊數字不一致。 |
| 6. Features | **Online Feature Store** (Databricks)<br>Powered by Lakebase. Model Serving looks features up automatically, so the store app only sends store and SKU.<br>[doc](https://docs.databricks.com/aws/en/machine-learning/feature-store/online-feature-store) | **SageMaker Feature Store, online** (AWS)<br>The online store of the same feature group serves the latest values with low latency.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/feature-store.html) | 官方文件：Online Feature Store 由 Lakebase 驅動。舊的 Online Tables 已不是主推做法。 |
| 6. Features | **Feature Store in Unity Catalog** (Databricks)<br>Feature Views (Public Preview) or feature tables governed in Unity Catalog. Point-in-time joins stop training from seeing the future, and models record which features they used.<br>[doc](https://docs.databricks.com/aws/en/machine-learning/feature-store/) | **SageMaker Feature Store, offline** (AWS)<br>Feature groups with an offline store in S3 for training. AWS docs point you to SageMaker Studio, not Unified Studio, when you need Feature Store.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/feature-store.html) | AWS 官方文件原文：需要 Feature Store 或 Canvas 時用 SageMaker Studio——資料端與 ML 端體驗仍分開。Databricks 的 feature 就是 UC 物件。 |
| 7. Train and register | **MLflow 3, managed** (Databricks)<br>Databricks-managed MLflow tracks every run, parameter and metric. MLflow 3 adds Logged Models and deployment jobs governed by Unity Catalog.<br>[doc](https://docs.databricks.com/aws/en/mlflow/) | **Managed MLflow on SageMaker AI** (AWS)<br>MLflow Apps (MLflow 3.x) or tracking servers. Models can auto-register into SageMaker Model Registry.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html) | 兩邊都用 MLflow。Databricks 是 MLflow 的原創者，並和 UC 原生整合。SageMaker Experiments 只剩 Studio Classic，不再是主要選項。 |
| 7. Train and register | **Many-models training** (Databricks)<br>groupBy(store, sku).applyInPandas fans out thousands of small LightGBM or Prophet models in parallel on Spark, each run logged to MLflow.<br>[doc](https://docs.databricks.com/aws/en/pandas/pandas-function-apis) | **SageMaker AI training jobs** (AWS)<br>Custom per-series training fanned out across training or processing jobs. For low-code, SageMaker Canvas forecasts per item ID. Amazon Forecast is no longer available to new customers.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/train-model.html) | 數萬條 store×SKU 時間序列 = many-models 模式，不是 Mosaic AI Training（那是 LLM 微調）。AWS 端：Amazon Forecast 已不開放新客戶，官方建議轉 SageMaker Canvas。 |
| 7. Train and register | **Models in Unity Catalog** (Databricks)<br>Model versions live in Unity Catalog with aliases and lineage back to features and tables. Promotion is an alias swap, so rollback is one line.<br>[doc](https://docs.databricks.com/aws/en/machine-learning/manage-model-lifecycle/) | **SageMaker Model Registry** (AWS)<br>Model package groups with versions and an approval status that pipelines check before deploying.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/model-registry.html) | Databricks：模型、表、特徵同一套權限。AWS：Model Registry 權限走 IAM，資料權限走 Lake Formation。 |
| 8. Serve | **Model Serving endpoint** (Databricks)<br>Serverless REST endpoint for intraday re-forecasts. It scales with demand, looks up online features itself and captures requests and responses for monitoring.<br>[doc](https://docs.databricks.com/aws/en/machine-learning/model-serving/) | **SageMaker AI real-time endpoint** (AWS)<br>Real-time endpoint with autoscaling, usually fronted by API Gateway and Lambda for the store app.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints.html) | Model Serving 同時支援 real-time 與 batch inference（官方文件）。延遲目標依 SLA 設計，不要引用沒依據的數字。 |
| 8. Serve | **Data quality monitoring** (Databricks)<br>Anomaly detection watches freshness and completeness of every table. Data profiling (formerly Lakehouse Monitoring) tracks drift on inference tables. Alerts trigger retraining.<br>[doc](https://docs.databricks.com/aws/en/data-governance/unity-catalog/data-quality-monitoring/) | **Data Capture + MLflow Apps + Evidently** (AWS)<br>SageMaker Model Monitor is no longer open to new customers. AWS's documented replacement: Data Capture to S3, open-source monitoring solutions built on SageMaker AI MLflow Apps and Evidently AI, CloudWatch alarms and Quick Sight dashboards.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/model-monitor-availability-change.html) | 大部分預測事故是資料晚到或缺漏，不是模型壞了——先監控資料，再監控模型。AWS 端注意：SageMaker Model Monitor 已不開放新客戶，替代方案要自己部署（MLflow Apps + Evidently + CloudWatch）。 |
| 8. Serve | **Batch inference job** (Databricks)<br>A Lakeflow Jobs task scores every warehouse and SKU 30 days ahead each night and writes a gold forecast table.<br>[doc](https://docs.databricks.com/aws/en/jobs/) | **SageMaker Batch Transform** (AWS)<br>Nightly batch transform triggered by SageMaker Pipelines or Step Functions. Results land in S3 and load into Redshift.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html) | 預測結果是一張「表」：ERP、BI、agent 讀的是同一份數字。 |
| 9. Use | **Store sales forecast** (business outcome)<br>Store managers see today's top-ups and staffing in a Databricks App that calls the endpoint.<br>[doc](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/) | **Store sales forecast** (business outcome)<br>A store app calls the endpoint through API Gateway and Lambda.<br>[doc](https://docs.aws.amazon.com/apigateway/latest/developerguide/welcome.html) | 成功指標是缺貨率、報廢率、人力成本，不只是模型準確度。 |
| 9. Use | **Genie + Agent Bricks** (Databricks)<br>Planners ask why a forecast moved and Genie answers over governed data. A replenishment agent built with Agent Bricks calls the forecast endpoint and drafts orders for approval. Models and tools go through Unity Gateway.<br>[doc](https://docs.databricks.com/aws/en/agents/) | **Amazon Quick + Bedrock AgentCore** (AWS)<br>Quick answers questions and hosts dashboards. A replenishment agent on AgentCore Runtime uses Gateway tools to call the endpoint, with Policy and Evaluations around it.<br>[doc](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) | 重點：human-in-the-loop、工具治理（Unity Gateway 對 AgentCore Gateway + Policy）、評估（MLflow 3 對 AgentCore Evaluations）。Unity Gateway 可以用客戶既有的 Amazon Bedrock 容量——共存點。 |
| 9. Use | **Warehouse inventory forecast** (business outcome)<br>Suggested orders sync back to the ERP for planners to approve. AI/BI dashboards show coverage and stock-out risk.<br>[doc](https://docs.databricks.com/aws/en/dashboards/) | **Warehouse inventory forecast** (business outcome)<br>Suggested orders go back to the ERP. Amazon Quick Sight dashboards for planners.<br>[doc](https://docs.aws.amazon.com/quick/latest/userguide/what-is.html) | ERP 仍是下單系統；預測只產生「建議」，由採購核准。 |

## Layers under and over every step

| layer | Databricks | AWS | 學習重點 |
|---|---|---|---|
| Where people work and how jobs run | **Databricks workspace + Lakeflow Jobs**<br>Notebooks, SQL editor, pipelines and dashboards in one workspace. Lakeflow Jobs orchestrates ingest, train, score and refresh as one DAG.<br>[doc](https://docs.databricks.com/aws/en/jobs/) | **SageMaker Unified Studio**<br>One IDE that brings together Glue, EMR, Athena, Redshift, MWAA, Bedrock and SageMaker AI.<br>[doc](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/what-is-sagemaker-unified-studio.html)<br><br>**SageMaker AI Studio**<br>AWS docs: use SageMaker Studio when you need Feature Store or Canvas.<br>[doc](https://docs.aws.amazon.com/next-generation-sagemaker/latest/userguide/what-is-sagemaker.html)<br><br>**Pipelines / Step Functions**<br>SageMaker Pipelines or Step Functions orchestrate training, approval and batch scoring.<br>[doc](https://docs.aws.amazon.com/sagemaker/latest/dg/pipelines.html) | Databricks：一個 workspace；AWS：Unified Studio 管資料與分析，Feature Store / Canvas 仍在 SageMaker AI Studio（官方文件寫明）。 |
| Governance | **Unity Catalog**<br>One permission model and lineage graph for tables, volumes, features, models, functions and serving endpoints, extended to agents and MCP tools through Unity Gateway. Row filters, column masks and audit.<br>[doc](https://docs.databricks.com/aws/en/data-governance/unity-catalog/) | **SageMaker Catalog**<br>Discovery, publish and subscribe, data quality and lineage across data and AI assets.<br>[doc](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/working-with-business-catalog.html)<br><br>**Lake Formation + Glue Data Catalog**<br>Fine-grained table, column and row permissions on S3 data, plus technical metadata.<br>[doc](https://docs.aws.amazon.com/lake-formation/latest/dg/what-is-lake-formation.html)<br><br>**IAM**<br>Who can call Feature Store, training, Model Registry and endpoints.<br>[doc](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html) | 這是最關鍵的差異：Databricks 一套權限 + lineage 從 POS 表追到 endpoint；AWS 治理是三層組合，要對齊。要公平、講事實。 |
| Storage | **Your Amazon S3, open formats**<br>Delta Lake tables in the customer's own S3 buckets. Compute, serverless or classic, is separate from storage. | **Amazon S3 + S3 Tables**<br>General purpose buckets plus table buckets that store Apache Iceberg tables with automatic compaction.<br>[doc](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-tables.html) | 兩邊資料都在客戶自己的 S3、開放格式——Databricks on AWS 不是搬走資料，是在同一份 S3 上加平台。 |
